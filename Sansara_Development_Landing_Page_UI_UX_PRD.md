# Sansara Development — Landing Page UI/UX PRD
## Driessen Architectuur–Inspired Direction

> **Purpose:** Create a new landing page for **Sansara Development** using the same high-level design principles observed on Driessen Architectuur: editorial architecture presentation, generous whitespace, oversized typography, strong project imagery, clear section rhythm, restrained navigation, and a premium studio/developer feel.
>
> **Important:** This is a design-direction reference, not a pixel-for-pixel copy. Do not reproduce Driessen's exact copy, assets, branding, or proprietary visual details.

---

## 1. Project Overview

**Brand:** Sansara Development  
**Website:** sansaradevelopment.com  
**Page:** Landing page / Home only

### Current business positioning

Sansara Development is a Bali real-estate developer focused on durable construction, architectural quality, technology, long-term value, and quality of life.

The current website communicates:
- Technology-driven real estate
- Architecture & lifestyle
- Long-term investment value
- Proprietary construction technology
- LGSF / Cold-Formed Steel construction
- Solvyn City as the flagship project
- Residence types
- Construction progress
- Construction guarantees
- Legal / transaction transparency
- FAQ and contact

The redesign should make the brand feel **more architectural, premium, calm, editorial, and intentional**, while keeping the important real-estate/investment information accessible.

# 2. Core UX Direction

## Design keywords

- Architectural
- Editorial
- Minimal
- Premium
- Quiet luxury
- Contemporary
- Spacious
- Image-led
- Trustworthy
- Tropical but sophisticated
- Technology-driven without looking overly technical

## Main UX principle

**Less information per screen, stronger hierarchy.**

The current Sansara website puts many topics into one long landing page. The new direction should create more breathing room between ideas.

Instead of:

`Headline → many statistics → technology → project → residences → construction → why us → FAQ → contact`

Use:

`Brand statement → philosophy → flagship project → expertise → selected residences → construction → trust → CTA`

Each section should feel like a separate editorial chapter.

## Overall feeling

The interface should feel closer to an **architecture studio / premium property journal** than a traditional real-estate sales website.

# 21. Motion & Interaction

Motion should feel architectural and restrained.

## Page entrance

Elements fade and move upward by approximately 16–30px.

Duration:
`600–900ms`

Easing:
`cubic-bezier(0.22, 1, 0.36, 1)`

## Images

On scroll:
- Slow scale from `1.05 → 1`
- Very subtle vertical movement

## Project cards

Hover:
- Image scale `1 → 1.04`
- Arrow moves `8–12px`
- Text remains stable

## Navigation

Header transitions from transparent to solid when scrolling.

## Avoid

- Fast bouncing animations
- Excessive text animations
- Scroll hijacking
- Heavy 3D effects
- Constant parallax
- Excessive cursor effects

# 27. Development Requirements

## Technology Stack — IMPORTANT

This project should be built using a **simple front-end stack**.

### Required

- **Basic HTML5**
- **Tailwind CSS via CDN Script**
- **Vanilla JavaScript**
- No React
- No Next.js
- No build system required
- No Tailwind CLI required

### Tailwind CSS

Use the Tailwind CSS CDN script directly in the HTML.

Example:

```html
<script src="https://cdn.tailwindcss.com"></script>
```

The project should use Tailwind utility classes directly inside the HTML markup.

If custom Tailwind configuration is needed, configure it through the CDN script:

```html
<script>
  tailwind.config = {
    theme: {
      extend: {
        // Custom Sansara design tokens
      }
    }
  }
</script>
```

### JavaScript

Use **Vanilla JavaScript only** for:

- Mobile navigation
- Sticky header behavior
- Scroll interactions
- Image/video interactions
- Accordions
- Residence carousel
- Testimonial slider
- Smooth scrolling
- Intersection Observer animations
- Responsive interaction states

Do not introduce React, Vue, Angular, jQuery, or other JavaScript frameworks.

### Recommended File Structure

```text
sansara-development/
│
├── index.html
├── css/
│   └── custom.css
├── js/
│   └── main.js
└── assets/
    ├── images/
    ├── videos/
    └── icons/
```

### HTML

The landing page should be contained primarily in:

```text
index.html
```

Use semantic HTML:

```html
<header>
<nav>
<main>
<section>
<article>
<footer>
```

### Custom CSS

Tailwind CSS should handle the majority of styling.

Use:

```text
css/custom.css
```

only for styles that are difficult or impractical to express with Tailwind utilities, such as:

- Custom animations
- Complex image masks
- Special typography behavior
- Browser-specific adjustments
- Fine visual details

Do not recreate the entire Tailwind system in custom CSS.

### Vanilla JavaScript

Keep JavaScript modular and lightweight.

Example:

```text
js/main.js
```

Use modern browser APIs such as:

- `querySelector`
- `addEventListener`
- `IntersectionObserver`
- `classList`
- `requestAnimationFrame`

Avoid unnecessary dependencies.

### Performance Principle

The website should be capable of running as a straightforward static website.

The goal is:

**HTML + Tailwind CDN + Vanilla JavaScript + optimized assets**

rather than a complex application architecture.

# 28. Accessibility

Ensure:

- Semantic HTML
- Keyboard navigation
- Visible focus states
- Sufficient text contrast
- Alt text for meaningful images
- Reduced-motion support
- Accessible accordion controls
- Accessible mobile menu
- Buttons have clear labels
- Avoid text embedded inside images

---

# 29. Performance

Because the design is highly image-driven:

- Use Next.js Image
- Use responsive image sizes
- Use WebP/AVIF where appropriate
- Lazy-load below-the-fold images
- Preload only the hero asset
- Compress video
- Avoid autoplay video with large file sizes unless optimized
- Use poster images for video
- Avoid unnecessary animation libraries
